# US-156070-01 - Listar acessórios TCO tipo Bonificação no modal da Solicitação de Compra

---

# Referências

## Feature

* [156070](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/156070) — [12905761237] Inserir Bonificação na Solicitação de Compras

## Artefatos

* Dependência funcional: [146136](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/146136) — TCO > Veículo > Acessórios — categoria **Bonificação**
* Cadastro origem (dado novo): **TCO > Veículo > Acessórios** (`/adicionais`)
* Tela impactada: **Solicitação de Compra > Definição de Ativos > modal Confirmar Solicitação > aba Bonificação**
* Print do modal atual: anexo da Feature [156070](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/156070)
* Regras da Feature cobertas: RG01 a RG15 (RG16 permanece fora — demais campos do modal)

---

# Escopo

Na aba **Bonificação** do modal **Confirmar Solicitação** (Definição de Ativos), trocar a origem do select **Descrição** para acessórios ativos do tipo **Bonificação** do TCO, com busca pelo nome, exibição do Valor Estimado, carga desse valor no campo **Valor** (editável, inclusive `R$ 0,00`), impedimento de acessório repetido na mesma confirmação e preservação das linhas gravadas pelo cadastro antigo, sem migração.

**Fora de escopo desta US:**

* Alterar o cadastro **TCO > Veículo > Acessórios**
* Migrar bonificações legadas para acessórios TCO
* Usar o cadastro antigo de bonificações do SIMA como origem do select
* Alterar as abas Dados, Condições de Pagamento e Previsão das etapas
* Relatórios de bonificação
* Nova permissão

---

# Regras de Negócio

## RN01

O select **Descrição** lista somente acessórios de **TCO > Veículo > Acessórios** cujo **Tipo de Acessório** seja **Bonificação**.

Acessórios dos tipos **Geral** e **Rastreador** não aparecem.

O cadastro antigo de bonificações do SIMA não é origem deste select.

## RN02

Cada opção do select exibe o **Nome** do acessório e o **Valor Estimado**, no formato `Nome — R$ 9.999,99`.

**Exemplo:** acessório `IPVA` com Valor Estimado `R$ 1.200,00` → opção `IPVA — R$ 1.200,00`.

Na linha já adicionada de dado novo, a descrição exibida é o **Nome** do acessório.

## RN03

O select permite busca: ao digitar, a lista é filtrada pelo **Nome** do acessório, usando o texto informado.

**Exemplo:** cadastro com `Despachante`, `Frete` e `IPVA`. Usuário digita `desp` → permanece a opção de `Despachante`.

## RN04

O select lista apenas acessórios do tipo **Bonificação** **ativos**. Acessórios inativos não entram como opção.

## RN05

Ao selecionar um acessório no select, o campo **Valor** daquela linha é preenchido com o **Valor Estimado** vigente do acessório.

**Exemplo:** `IPVA` com Valor Estimado `R$ 1.200,00` → Valor recebe `1.200,00`.

## RN06

Após o preenchimento automático (RN05), o campo **Valor** permanece habilitado. O usuário pode aumentar, diminuir ou manter o valor carregado.

O valor gravado na solicitação é o da linha no momento de salvar o modal. Alteração posterior do Valor Estimado no cadastro do acessório não atualiza bonificações já gravadas.

**Exemplo:** estimado `R$ 1.200,00` → usuário altera para `R$ 1.000,00` → persiste `1.000,00`.

## RN07

Se o Valor Estimado do acessório for `R$ 0,00`, o campo **Valor** carrega `0,00` e o sistema permite salvar a linha.

## RN08

Se o usuário trocar o acessório já selecionado na linha, o **Valor** é substituído pelo Valor Estimado do novo acessório. O valor editado anteriormente nessa linha é descartado.

**Exemplo:** linha `Frete` / `R$ 400,00` (alterado). Troca para `IPVA` (estimado `R$ 1.200,00`) → Valor passa a `1.200,00`.

## RN09

Não é permitido incluir o mesmo acessório mais de uma vez na mesma confirmação (mesmo modelo / item).

O acessório já usado em outra linha da lista não aparece no select das demais linhas.

Ao remover a linha, o acessório volta a aparecer no select.

**Exemplo:** já existe `IPVA` na lista. O select de uma nova linha não oferece `IPVA`. Pode oferecer `Frete`.

## RN10

Permanece permitido adicionar mais de uma bonificação no mesmo modal (botão **Adicionar bonificação**), desde que cada linha seja um acessório diferente (RN09).

## RN11

Em cada linha nova:

* **Descrição** (acessório TCO) é obrigatória
* **Valor** é obrigatório (aceita `0,00` — RN07)

Não é permitido salvar a linha nova sem acessório selecionado.

## RN12

* O ícone de excluir remove a linha, no mesmo comportamento atual.
* Em modo somente leitura, select, valor, adicionar e excluir permanecem bloqueados.

## RN13

Solicitações que já possuem bonificação gravada pelo cadastro antigo (dado legado) continuam funcionando. Não há migração para acessório TCO.

* A linha legada permanece visível com a **descrição** e o **valor** já persistidos, mesmo que o item não exista no cadastro TCO.
* O valor da linha legada continua editável e persistível.
* Se o usuário mantém a linha legada sem trocar a descrição pelo select, o sistema grava a mesma origem antiga e o valor informado.
* Se o usuário troca a descrição da linha pelo select, a linha passa a ser dado novo (acessório TCO) e aplicam-se RN05, RN07 e RN08.
* Se o usuário exclui a linha legada, não consegue recolocá-la pelo select, a menos que exista acessório TCO ativo equivalente.
* A última solicitação com dado legado é de **07/2025**.

## RN14

Se não existir nenhum acessório ativo do tipo **Bonificação**, o select não apresenta opções novas. Linhas legadas (RN13) continuam visíveis. Não é possível incluir bonificação nova até existir ao menos um acessório ativo desse tipo.

# Critérios de Aceite

## CA01

Dado que existem acessórios ativos `IPVA` (Valor Estimado `R$ 1.200,00`) e `Frete` (Valor Estimado `R$ 500,00`) do tipo **Bonificação**, e um acessório `Película` do tipo **Geral**

Quando o usuário abre o select **Descrição** na aba Bonificação

Então o select apresenta `IPVA — R$ 1.200,00` e `Frete — R$ 500,00`

E não apresenta `Película` nem itens do cadastro antigo de bonificações

## CA02

Dado que o select está aberto e existem os acessórios ativos `Despachante`, `Frete` e `IPVA` do tipo **Bonificação**

Quando o usuário digita `desp`

Então a lista filtrada contém `Despachante` e não contém `Frete` nem `IPVA`

## CA03

Dado que o acessório `IPVA` está ativo, tipo **Bonificação**, com Valor Estimado `R$ 1.200,00`

Quando o usuário seleciona `IPVA` em uma linha nova

Então o campo **Valor** da linha é preenchido com `1.200,00` e permanece editável

## CA04

Dado que a linha foi preenchida com `IPVA` e Valor `1.200,00`

Quando o usuário altera o Valor para `1.000,00` e salva o modal

Então a solicitação persiste a bonificação com descrição `IPVA` e valor `1.000,00`

## CA05

Dado que o acessório `Taxa zero` está ativo, tipo **Bonificação**, com Valor Estimado `R$ 0,00`

Quando o usuário seleciona `Taxa zero` e salva o modal sem alterar o Valor

Então a linha é persistida com valor `0,00`

## CA06

Dado que a linha tem `Frete` e Valor `400,00` (alterado pelo usuário), e `IPVA` tem Valor Estimado `R$ 1.200,00`

Quando o usuário troca o select da linha para `IPVA`

Então o Valor da linha passa a `1.200,00`

## CA07

Dado que a confirmação já possui uma linha com o acessório `IPVA`

Quando o usuário adiciona outra linha e abre o select

Então `IPVA` não aparece nas opções

E `Frete` (se ativo e ainda não usado) aparece

## CA08

Dado que a confirmação possui uma linha com `IPVA`

Quando o usuário exclui essa linha e abre o select de uma nova linha

Então `IPVA` volta a aparecer nas opções

## CA09

Dado que o usuário adicionou uma linha e não selecionou acessório

Quando tenta salvar o modal

Então a linha nova não é persistida sem descrição

## CA10

Dado que o modal está em modo somente leitura

Quando o usuário visualiza a aba Bonificação

Então select, Valor, **Adicionar bonificação** e excluir permanecem bloqueados

## CA11

Dado que existe uma solicitação com bonificação legada (cadastro antigo), com descrição `Despachante` e valor `800,00`, e esse item não existe como acessório TCO

Quando o usuário abre o modal em edição

Então a linha exibe `Despachante` e `800,00`

E o select de inclusão não lista o item legado, apenas acessórios TCO ativos do tipo **Bonificação**

## CA12

Dado que a linha legada `Despachante` / `800,00` está visível

Quando o usuário altera somente o Valor para `750,00` e salva, sem trocar a descrição pelo select

Então a solicitação persiste a mesma origem legada com valor `750,00`

E a descrição continua `Despachante`

## CA13

Dado que a linha é legada `Despachante` / `800,00` e existe acessório TCO `IPVA` com Valor Estimado `R$ 1.200,00`

Quando o usuário troca o select da linha para `IPVA` e salva

Então a linha deixa de ser legado e persiste como acessório TCO `IPVA` com valor `1.200,00` (ou o valor que o usuário editar depois da troca)

## CA14

Dado que a linha é legada e o usuário a exclui, e não existe acessório TCO com o mesmo nome

Quando o usuário abre o select para incluir novamente

Então o item legado não aparece e não é possível recolocá-lo

## CA15

Dado que não existe nenhum acessório ativo do tipo **Bonificação** e a solicitação possui uma linha legada

Quando o usuário abre a aba Bonificação

Então a linha legada permanece visível e o select não apresenta opções novas

## CA16

Dado que o acessório `IPVA` está **inativo**, tipo **Bonificação**

Quando o usuário abre o select

Então `IPVA` não aparece nas opções

## CA17

Dado que uma solicitação já gravada tem bonificação nova `IPVA` com valor `1.000,00`, e o Valor Estimado do acessório no TCO foi alterado depois para `R$ 1.500,00`

Quando o usuário reabre o modal sem trocar o acessório da linha

Então o Valor exibido permanece `1.000,00`

# Exemplos de Negócio

## Exemplo 01

### Cenário

Incluir bonificação nova a partir do TCO e alterar o valor.

### Entrada

* Acessório TCO ativo, tipo Bonificação: `IPVA`, Valor Estimado `R$ 1.200,00`
* Usuário seleciona `IPVA` e altera Valor para `1.000,00`

### Resultado Esperado

* Select mostrou `IPVA — R$ 1.200,00`
* Valor carregou `1.200,00` e depois persistiu `1.000,00`

## Exemplo 02

### Cenário

Impedir o mesmo acessório duas vezes na mesma confirmação.

### Entrada

* Linha 1: `IPVA`
* Usuário adiciona linha 2 e abre o select

### Resultado Esperado

* `IPVA` não aparece na linha 2
* Outros acessórios ativos do tipo Bonificação, ainda não usados, aparecem

## Exemplo 03

### Cenário

Editar solicitação com dado legado (última ocorrência conhecida: 07/2025).

### Entrada

* Solicitação com bonificação do cadastro antigo: descrição `Despachante`, valor `800,00`
* Não existe acessório TCO `Despachante`

### Resultado Esperado

* Linha visível com `Despachante` / `800,00`
* Usuário pode alterar só o valor e salvar sem migrar
* Select de nova linha não lista `Despachante`

## Exemplo 04

### Cenário

Trocar acessório na linha e recarregar o Valor Estimado.

### Entrada

* Linha: `Frete` / `400,00` (valor já alterado)
* `IPVA` com Valor Estimado `R$ 1.200,00`

### Resultado Esperado

* Ao trocar para `IPVA`, Valor passa a `1.200,00`

# Observações

* Frontend e API devem aplicar as mesmas regras de origem (só TCO tipo Bonificação, só ativos) e de unicidade na mesma confirmação.
* O destino técnico do vínculo do dado novo (identificador do acessório TCO) é decisão de implementação, desde que a origem do select seja o cadastro da [146136](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/146136) e o legado não seja migrado.
* Dependência: [146136](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/146136) disponível, com acessórios do tipo Bonificação cadastrados, para haver opções novas (RN14).
* Ao registrar no backlog do AtivosCompraMobilizacao, prefixar o título com `[A]` se for o padrão do time.
* A Feature [156070](https://dev.azure.com/aguiabranca/AtivosCompraMobilizacao/_workitems/edit/156070) precisa da aprovação formal no Azure DevOps antes do registro desta US no backlog.
