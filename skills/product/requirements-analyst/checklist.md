# Checklist — Requirements Analyst

Use antes de entregar cada User Story.

## Entrada (Feature)

- [ ] Feature aprovada pelo negócio
- [ ] Identificador da Feature informado (ex.: `FEAT-XXX`)
- [ ] Lacunas da Feature sinalizadas (se houver) — não prosseguir sem registro

## Decomposição

- [ ] Decisão de uma ou múltiplas USs documentada com justificativa
- [ ] Critérios de `product/us-guidelines.md` aplicados

## User Story

- [ ] Título segue `US-{FEATURE}-{ORDEM} - {DESCRIÇÃO}`
- [ ] Referência à Feature preenchida
- [ ] Artefatos complementares referenciados por link
- [ ] Escopo definido e limitado a esta entrega
- [ ] Regras de negócio sem ambiguidade
- [ ] Critérios de aceite em Dado/Quando/Então, testáveis pelo QA
- [ ] Exemplos incluídos quando há cálculos, datas, ordenações, aprovações ou integrações
- [ ] Observações com dependências e restrições relevantes

## Qualidade

- [ ] Nenhuma regra de negócio inventada
- [ ] Dúvidas para o negócio listadas separadamente
- [ ] Inconsistências na Feature sinalizadas (se houver)
